# Codex 对话图片归档

把对话里的图片保存成项目里的真实文件，让图片和代码一起随Git版本保留。此技能只负责图片整理与说明，不规定项目美术风格、游戏机制或实现方式。

## 范围

- 当前对话用户上传的图片、剪贴板图片。
- Codex或工具生成的图片，含临时输出、概念图、修改版本。
- Codex展示、查看或用于评审的预览图、实机截图、动画阶段图和对照图。
- 本对话中实际使用的其他参考图片。
- 用户指定多个对话时，用可用对话读取工具定位其图片来源；没有授权时不向其他对话发消息。
- 根据对话记录、工具返回路径及本次输出定位图片，不批量扫描复制无关临时文件。图片丢失时记录缺失，不能把替代图片冒充原件。

## 文件夹与命名

优先沿用用户指定的项目目录；未指定时在Git仓库内用 `assets/交互图片/<技能名字>/`。已有 `assets/vfx/<技能名字>/` 等归档时沿用，不重复新建一套。

- 主文件夹以技能名字命名；非技能任务用主题名字。不用聊天ID或日期代替可读主题名字。
- 同一主题内可分 `用户参考图/`、`生成设计图/`、`预览实机图/`；已有分类可保留。
- 图片命名为“技能名_等级或阶段_用途图_版本”，如 `天狐雷劫_Lv4_九尾参考图_v01.png`、`天狐雷劫_Lv4_爆发预览图_v02.png`。
- 对照图写清范围，如 `雷符_Lv1至Lv4_对照图_v01.png`。
- 版本用v01、v02递增，或用户现有规范。不能覆盖之前的交互图片。归档同一源文件时核对内容，完全相同的图片可共用一个文件并记录多次使用。

## 保存

1. 从本次对话列出实际图片及可访问源路径，标明来源和用途。
2. 将临时目录、工具输出目录、用户附件和工作预览图复制到项目归档目录。保留原件和原始清晰度，不为归档改变图片内容。
3. 对会被后续截图覆盖的工作文件，及时复制为独立版本。没有保存的旧版无法恢复时如实说明。
4. 新归档优先使用可读图名；重命名已有文件时同步README与清单中的相对链接，避免破坏项目中实际引用。
5. 用户后续继续本主题时，将新上传、生成和展示的图片追加到同一技能文件夹；完成本次工作前检查全部新图片已保存。

## 图片总结

每个技能目录维护 `README.md`，以简单表格列出：

| 图片名字 | 类型/来源 | 用途与版本状态 |
|---|---|---|
| xxx参考图 | 用户上传 | 哪些细节作为参考 |
| xxx设计图 | 工具生成 | 设计方向，是否认可或否定 |
| xxx预览图 | 实机/工具预览 | 阶段或时点，属于哪一版 |

- 图片名字链接到归档内真实文件，使用相对路径。
- 保留用户明确表达的评审结论，不自行声称图片或实现已被认可。
- 可用 `manifest.json` 记录主题名、文件相对路径、来源文件名、来源类型、版本、状态和内容哈希；无需保存机器临时路径或聊天私人内容到仓库。
- 不把每次整理变成项目设计总结；说明重点是“什么图、来自哪里、干什么、哪一版”。

## Git与检查

- 图片必须位于目标仓库内，不能只给临时路径或外部工具链接。
- 检查清单对应文件都存在、README链接正确、没有同名覆盖、Git没有忽略目标图片。
- 已有.gitignore会排除图片时，仅处理归档路径所需例外，避免放开整个临时目录。
- 大文件或已有LFS规则按仓库约定处理；不擅自配置LFS或删除原图。
- “随Git版本走”意味着归档文件可随项目提交；只有用户明确要求提交/推送时才执行Git提交或远程推送。
- 最终给技能名文件夹与README链接，并报告已保存数量、缺失图片（如有）和提交状态。
