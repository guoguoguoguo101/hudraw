# 符术交互 · 试验画境：第一轮性能优化

2026-10-19。只对 `game.interactionPractice` 启用。关卡、原自由试符继续采用原有圆阵和画笔渲染路径。玩法伤害、持续时间、技能上限、识别和墨水计费不变。

## 本次实现

- 圆 Lv1–4 静态装饰使用 `StaticArtAtlas`：原始矢量生成共享图集，原来的节点位置、透明度、旋转、前后景切换继续生效。没有替换成整张静态技能图。
- 图集准备按每次约 1.5ms 的软预算分摊，单次 GPU 分配可能超出该预算；缓存未准备好或空间不足时继续显示原始矢量，不删除装饰。每次最多处理 256 个待处理构件。
- 每个试验场图集最多四页 1024×1024，分辨率上限 1.5；颜色纹理约最多 36MiB，驱动/抗锯齿额外占用未包含。不同等级共同使用此上限，容量不足回退原始图形。
- 两个及以上圆阵时，相同动画时刻的九尾、狐火和环火共享 `GraphicsContext` 及中间几何结果。动画时间保留到微秒量级，不降动画帧率；各自的时间、位置、淡入淡出独立。单个圆继续复用自身路径缓冲，避免共享缓存的额外成本。
- `SharedGeometry` 回收没有活跃节点引用的旧帧，超过 1024 项时向 768 项回收；保留活跃引用，因此不是严格的 1024 项硬截断。场景内现有技能上限限制同时活跃路径。退出试验场释放共享几何及图集。
- 长笔迹在输入与样式不变时复用计算结果和画面；继续移动、输入数组压缩/替换、收笔、干笔、渐隐、换笔设置时正确刷新。细毛线按颜色和近似宽度批处理，宽度舍入至 0.01 世界单位，保留双层墨色与细毛。
- 仍在移动的长笔迹目前仍会重建轮廓，本轮没有声称完成整条笔迹的增量网格系统。原始手势点、付费路径、斩击路径未改动。
- 圆 Lv5 不做静态图集转换，保留其特殊分层演出；部分复用的火焰路径在多个圆并存时可使用共享几何。其余技能视觉没有删减。

## 画面与行为验证

`npm run test:performance:preview` 在同一个版本中切换优化开/关，比较护身圆开场/持续/十圆叠加、远处封妖圆开场/持续/破阵、400 点笔迹，共七组截图。截图及原始差异在 `screenshots/experiment-performance/verification.json`。

本次画面每像素 RGB 最大通道差的全图均值为约 0.07–1.35 / 255；差异超过 24 / 255 的像素占比均低于 1.5%。图集采样和细线批处理会产生轻微像素差异，不承诺逐像素完全一致。已人工查看九尾护阵截图，确认九尾、符纸、火焰、环绕狐影、云纹和阵纹仍在。

`tests/shared-geometry.ts` 检查相同帧共享、不同时间互不修改、活跃旧帧保护、回收上限、清理及异常后的作用域隔离。原有全套逻辑测试通过。

真实指针的保底划斩检查通过。直线/三角交互浏览器检查首次在缩放手势场景失败一次，单独重跑通过；给该断言增加了手势坐标、识别结果与绘制边界输出，保留诊断信息，没有为通过测试修改游戏识别规则。

## 同条件性能对照

数据为开发构建、桌面 Edge 无头浏览器、GTX 1060、430×932 画幅、1.5 倍分辨率。每场景先运行 55 帧，再记录 45 帧，覆盖逐步准备图集后的状态。

对照文件：`combat-legacy-2026-10-19.json`、`combat-optimized-2026-10-19.json`。以下为阶段中位数；相加仅是典型 CPU 阶段合计，不是整帧分位数，也不包含 GPU 异步完成时间。

- 10 个护身圆 Lv4：更新 4.3 → 2.4ms，提交 22.3 → 8.7ms，典型合计 26.6 → 11.1ms，减少约 58%；绘制调用 748 → 424。
- 1 个护身圆：更新 0.7 → 0.7ms，提交 2.4 → 2.1ms。
- 10 个封妖圆 Lv4：更新 2.8 → 1.8ms，提交 8.4 → 7.0ms，典型合计 11.2 → 8.8ms，减少约 21%。
- 10 个封妖圆 + 35 只怪：更新 3.9 → 2.8ms，提交 10.3 → 8.6ms；此处不包含战斗逻辑，不能当作完整战斗帧率。
- 400 点停留笔迹：更新 2.4 → 接近计时器分辨率，提交 8.4 → 约 0.2ms；主要收益来自不再重建未变化的笔迹。
- 400 点持续变化的模拟笔迹：更新 2.4 → 1.3ms，提交 8.2 → 7.3ms。此组每帧替换输入数组强制重建，更接近长笔迹持续移动的压力，不应拿停留结果宣称所有画笔场景有同等提升。

首次准备图集仍有开销。本次单个护身圆首次创建/渲染约 29.7 → 35.7ms，十圆同帧创建约 121.2 → 110.7ms；这不是每次实际施放的延迟保证。缓存保留在同一试验场的重开之间，退出试验场释放。手机及微信真机帧率、显存峰值仍需实际设备验证。

## 代码入口与后续接入关卡

- `src/rendering/shared-geometry.ts`：独立的动画几何复用模块。
- `src/rendering/static-art-atlas.ts`：原图形的共享图集、容量与渐进准备。
- `src/rendering/circle.ts`：本场景启用条件、原始图形回退及释放。
- `src/rendering/spirit-pen.ts`：笔痕缓存与细毛批处理。
- `GameView.experimentalOptimizations` 默认开启，只在试验画境生效，可供 QA 做同版本对照，不是玩家设置。

以后接入正式关卡时，可以复用这些渲染模块并调整场景启用条件；本轮没有把优化全局打开。下一轮优先评估持续移动笔迹的增量网格、图集更合理的装箱/去重、移动设备资源峰值，再决定是否需要降低重复装饰数量。
