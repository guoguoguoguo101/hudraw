# 高等级画笔性能优化

问题集中在高等级留墨的矢量重绘：长寿命墨段每帧分别提交多层笔画、金线和花雷装饰，重复生成几何。喷墨/泼墨已有数量上限；同一压力场景下，伤害计算明显轻于渲染提交，优先优化测得的渲染瓶颈。

## 修改

- 同颜色、宽度、等级、透明度档位的墨段合并路径；删除一层低对比阴影，保留墨底、内色、金/雷脉络。
- 地面墨迹的渐隐与装饰以每秒 20 次更新；新笔迹和重描立即刷新。沿路流墨仍逐显示帧移动。伤害判定保持原节奏。
- 叶片、旁枝和亮点各设独立全局装饰上限，避免跟随墨段数量无限堆叠。
- 缓存检查模型、笔迹版本、墨段数量、时间、画质和边界；重开、过期、布局切换不会保留旧墨。
- 技能伤害、范围、墨迹持续时间、完整路径与升级数值不变。

## 对照数据

Edge 无头浏览器，390×844、设备像素比 2，四项技能 Lv4、32 个请求生成的高血量敌人（实际数量受生成规则限制）、连续模拟画线后留下 144 段墨迹。每组预热 20 帧，再取 80 帧样本。数值是桌面 CPU 构建/渲染提交耗时，不是手机帧率或 GPU 时间。

| 场景 | 优化前绘制指令中位数 | 优化后 | 渲染提交中位数前/后 |
| --- | ---: | ---: | ---: |
| 朱砂留墨 | 653 | 23 | 7.3 / 0.7 ms |
| 花雷留墨 | 947 | 65 | 6.8 / 0.6 ms |

持续新增笔迹的附加压力测试中，花雷留墨指令中位数 83，渲染提交中位数 3.5 ms。新笔迹立即绘制，因此持续画线比停笔保留墨迹的开销高。

原始报告与截图：`screenshots/brush-performance/{before,after,active-after}.{json,png}`。

## 验证

- `npm run build`、`npm run build:wechat`、`npm run test:hualing`。
- `node scripts/check-ink-trail-performance.mjs`：密集混合墨迹绘制预算、完整路径、缓存复用、新输入、画质、布局、重新启用、重置及过期。
- `node scripts/profile-brush-upgrades.mjs`；设置 `PERF_ACTIVE=1` 测持续画线，`PERF_LABEL` 指定报告名。

真机改善幅度仍需在玩家原设备复测；此轮没有降低画面分辨率或削弱升级效果。
