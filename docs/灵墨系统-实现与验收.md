# 灵墨系统：实现与验收

2026-10-14。已根据本聊天确认接入当前游戏：3秒绘制上限，耗尽后按完整付费轨迹成符，练习场默认无限墨＋有限墨测试开关；不做流畅／完美分级。

## 实际行为

- 新局100点灵墨，原固定符纸资源、次数检查与充能条已替换。
- 手指按下先记录；过滤抖动后的路径达到战斗区宽度7%才扣基础6点和此前路径费用。之后每1倍画幅扣15点，逐段实时扣费，停笔不扣。
- 普通正式成符返还10%，最多7点，净成本至少6点。真实余额立即增加；局部金光、墨条增长与“回墨 +N”约0.32秒完成。返还显示1位小数。
- 返还以实际释放为准，无目标也可释放和回墨，不按命中结算。保留现有识别quality及伤害系数，不修改技能等级、范围或伤害。
- 耗尽在当前线段上精确插值截断，后续轨迹仅暗淡余痕。整条付费轨迹符合直线条件仍可出刀；不能截取局部片段凑符。
- 松手或3秒先到先结算。超时等待原手指抬起，不重复施法，等待期间不恢复；抬指后再延迟0.35秒恢复。
- 短误触、UI触摸及不足8点的拒绝不扣墨，不重置恢复延迟。有效绘制从按下暂缓恢复，防止静止按住免费恢复。
- 系统取消、切后台、暂停、升级和屏幕尺寸改变回滚未提交成本；已经提交的超时笔不回滚。对局结束和后台期间不恢复，也不在返回时补算后台时长。
- 资源恢复和3秒截止使用活动真实时间，独立于战斗50%慢动作和受限的战斗补算步长。
- 依据用户在「整理灵笔绘符改造文档」中的后续明确要求，未成符不再产生曲线火焰或兜底攻击：费用保留、返还0、没有额外处罚，只做约0.12秒断符消散。该行为替代早期讨论的散墨攻击方案。

## 界面与测试入口

墨条位于战斗HUD生命条下方，旧三张符计数与符纸充能不再显示。既有生命、得分、剩余时间、等级和暂停保留，沿用长屏与安全区适配。回墨通知位于HUD内部，不能被前一笔动画覆盖当前余额或“灵墨不足”。

练习场左下“无限灵墨 · 切换有限”切换到有限墨测试；再点一次回到无限。无限模式显示∞；有限模式按正常资源规则计费，切换时取消当前未提交绘制并重置100点。

练习场“施放”辅助按钮按照完整生成手势的长度计费；有限模式不够支付完整手势时拒绝整次按钮施放，不扣余额。手绘仍按实时耗尽截断规则，二者不能混淆。

开发模式通过已有D键／手势调试开关显示灵墨调试面板；生产包不创建该面板。可以设为100／50／8／0、暂停或恢复自然回墨、开关返还视觉、按4点/秒调整恢复速度。设值会取消当前绘制；调试数据包括余额、状态、有效长度、本笔成本、返还、延迟、超时、耗尽、低墨时间和不足尝试次数。

## 验证方式与证据

- `npm test`：保留技能识别、伤害、升级、时钟、进度检查，并纳入灵墨验收。
- `npm run test:practice`：练习等级、无限资源与进度隔离。
- `npm run test:ink:preview`：本地开发服务启动后执行真实拖动和布局检查。
- `npm run build`、`npm run build:wechat`：类型检查及网页／微信包构建。
- `npm run test:wechat`：真实微信包在浏览器wx模拟中的启动、触摸、渲染、技能与诊断检查；不等同于真机微信验收。

新增14组灵墨检查覆盖：阈值与实时扣费；停笔；误触与微抖；快慢和采样密度；四笔皮肤一致；胡乱折返；精确耗尽点与一字斩；半圆失败；取消回滚；超时与原指针释放；暂停／升级／死亡／拒绝；真实时间恢复；返还上限与最低净成本；练习场有限／无限与自动按钮；回墨动画对新起笔和不足提示的正确衔接。

## 数值体验与限制

8点/秒、0.35秒延迟仍是测试起点，尚不宣称已完成真人节奏平衡。开发入口可直接对比8／12／16点每秒；若真机连续作战频繁出现无墨等待，优先提高恢复或降低成本，不另叠冷却条。1倍画幅正式符净耗18.9点，恢复这笔净消耗需约2.71秒（含延迟、不含绘制）；恢复到8点只代表可以起笔，不保证足够画完复杂符。

本地完整战斗模拟能在180秒完成试炼，但使用合成符形与自动策略，不能替代手绘体验验证。采样率差异只能保证合理容差，无法复原设备根本未采到的转弯。

品质分级、空间玩法与灵墨绑定、皮肤属性、复杂符术重做均未加入。微信真机刘海、安全区、原生触摸与手绘节奏需重新预览确认。
