# 《灵狐绘卷》灵墨能量系统方案讨论稿

版本：v0.1（实施补充）· 2026-10-14

状态：已获用户授权实施灵墨系统，具体交付见《灵墨系统-实现与验收》。原始讨论保留供追溯。

实施补充：用户在同项目的「整理灵笔绘符改造文档」聊天中明确取消未成符曲线火焰与攻击。最终未成符规则为：保留灵墨消耗、不返还、不额外处罚，原始笔迹约0.08～0.15秒断符消散，不产生兜底攻击。下文早期提到的散墨攻击不再作为实施要求。

原始讨论说明：本文依据用户任务书、两张界面参考图和当前项目代码整理。附件中“直接修改、一次完成”的指令属于原始任务书；本轮以用户最新要求为准：先形成文档、讨论规则，不修改游戏代码。

## 本轮已确认

- 绘制上限保持 **3秒**，不改成任务书的2秒。
- 练习场默认无限墨，提供“有限灵墨测试”开关。
- **已确认：耗尽后允许根据整条付费有效轨迹释放正式符。** 例如有效部分符合一字斩条件，就允许释放；不能截取局部线段强行成符，耗尽后的暗淡余痕不参与识别。松手或3秒到时只结算一次。
- 当前仍处于方案讨论阶段，不修改游戏代码。

## 1. 这次要解决什么

用最大100点的灵墨，替代现有固定符纸次数限制，让资源真正控制绘符与施法：

> 短笔省墨，长笔耗墨；未成符不回墨，正式成符回墨。

长度影响资源消耗；正式成符提供资源返还；快慢本身不增加费用或奖励。先完成消耗、返还、失败与UI反馈的完整闭环，再讨论雷电多折路径、圆阵大小与技能空间效果的联系。

本轮不实现任何游戏功能。后续首版也不做“流畅／完美”品质分级，不重做符形识别、伤害、技能范围、升级或大型演出。暂定所有正式成符统一返还10%；15%／20%仅作为后续品质方案保留，不作为首版验收要求。

### 最重要的三个验收点

1. **绘制过程中实时扣墨。** 有效起笔后，手指移动、路径增加、墨条减少同步发生；不能等松手才统一扣费。停笔不动不继续扣费。
2. **成符回墨清楚可见，但表现克制。** 立即增加真实资源，配合局部金光回流、墨条增长与“回墨 +N”小字；不能遮挡战斗或等待动画结束才能继续画。
3. **不能变成第二条等待条。** 8点/秒与0.35秒延迟只是测试起点；频繁缺墨、长时间被迫停手，应优先提高恢复速度或降低成本。需要记录实际等待，不能只检查公式是否正确。

| 项目 | 首版规则 |

| 品质分级 | 首版不做流畅／完美判定，不显示对应评级 |
| 画笔皮肤 | 不改变资源消耗与返还规则 |

全部参数集中配置，不散落在触控、技能和界面中。逻辑用浮点数计算；文字显示可以取整，但返还提示建议保留1位小数。

### 成本与返还

设战斗区逻辑宽度为W，过滤后的累计有效路径长度为L：

- 未达到有效起笔阈值：成本为0。
- 达到阈值后：总成本C = 6 + 15 × L/W。
- 绘制中只扣尚未扣除的增量，基础6点只扣一次。
- 普通成符返还R = max(0, min(C × 0.10, 7, C − 6))。
- 失败返还0；引擎拒绝或系统取消时按交易状态回滚，而不是当作玩家画错。

此处C必须是**实际成功扣除的成本**，不能拿灵墨耗尽后继续移动的理论长度算返还。

| 长度L/W | 总成本 | 普通成符返还 | 正式施法净成本 |
|---|---:|---:|---:|
| 0.2 | 9 | 0.9 | 8.1 |
| 0.5 | 13.5 | 1.35 | 12.15 |
| 1.0 | 21 | 2.1 | 18.9 |
| 1.5 | 28.5 | 2.85 | 25.65 |
| 2.0 | 36 | 3.6 | 32.4 |

“标准圆符消耗21点”只适用于周长恰好等于W的圆，不能当作所有圆的固定成本。首版按实际路径计费，但不因此改变圆阵半径或雷电攻击路径。

## 3. 一笔绘制的完整流程

### 3.1 按下：记录，不收费

先检查战斗状态、UI阻断、是否已有活动手指和起笔资源。允许起笔后，创建唯一gestureId，记录本笔轨迹，播放小型落笔反馈。

尚未达到7%阈值时不扣墨；此时松手视为误触，不施法、不惩罚。

### 3.2 有效起笔：第一次扣费

当前代码的战斗区宽度是720，所以阈值为50.4逻辑单位，与识别器现有50单位的最低路径要求接近，但两者不是同一规则：达到收费阈值不代表一定满足成符条件。

跨过阈值时，扣基础6点及此前已累计的长度费用。跨阈值的一次事件如果移动很远，也必须处理剩余灵墨不足的情况。

这是一次合理的起笔扣费；之后随路径增量持续减少，不能把整笔账单拖到松手。

### 3.3 行笔：资源与轨迹同步更新

以逻辑坐标、经过抖动过滤的移动距离计费。重描与折返都花墨，不因点数多而多收费，也不因轨迹被压缩、重采样而少收费。

计费累计值独立于为了识别和渲染而保留的点数组。不能每次重新平滑整条轨迹再反复计算成本，否则既可能重复收费，也可能把折返抹掉。

显示路径、付费有效路径、耗尽后的暗淡余痕要区分；可以复用现有输入与笔迹模块，不必重建手势系统。

### 3.4 收笔：识别完整有效轨迹，结算一次

正式符形 → 成功释放已有技能 → 提交成本 → 返还10% → 播放回墨反馈。

未成符 → 提交成本 → 复用已有散墨兜底 → 不返还、不另收失败费用。

成符返还以技能确实被接收并释放为准，不要求命中敌人。画得正确但当前没有目标，也应正常回墨。

若技能因非玩家原因被拒绝，需撤销未提交的资源交易；不能只因为识别成功就先发奖励。

## 4. 失败、耗尽和中断怎样处理

| 情况 | 资源处理 | 施法处理 |
|---|---|---|
| 点一下／不足有效起笔距离 | 0消耗、0返还 | 不施法，轻微墨点消散 |
| 有效轨迹未匹配正式符 | 保留成本、0返还 | 复用流焰／散墨爆散兜底，不增加失败罚款 |
| 复杂符未画完，但完整有效输入确实符合另一个符 | 按实际识别结果结算 | 不猜玩家意图；不能截取第一段强行成符 |
| 正常松手 | 提交一次 | 整笔识别、释放一次 |
| 超时 | 截止时提交一次 | 完整有效轨迹识别一次；等待原手指抬起 |
| 绘制途中耗尽 | 最多扣到0 | 截断付费轨迹；后续仅暗淡余痕，不能伤害或扩大法术路径 |
| 系统取消／切后台／打开阻断界面 | 回滚尚未提交的本笔费用 | 不释放，不获得成符返还 |
| 已超时提交后再取消 | 不回滚已提交账单 | 清理等待抬起状态，不重复释放 |
| 暂停、升级、死亡、胜负 | 取消未提交绘制；停止恢复 | 防止资源状态悬挂，已存在技能沿用原流程 |
| 墨不足8点尝试起笔 | 不扣剩余资源 | 轻闪与“灵墨不足”，按一次尝试触发，不能每帧刷提示 |

### 耗尽时必须补充的技术规则

如果某次移动需要3点，但只剩1点，不能接受整个路径段，也不能直接丢弃整段。应在线段上插值出剩余1点能够支持的末端，支付1点并保存这个截断点，随后转为暗淡余痕。

暗淡余痕不参与正式识别、散墨攻击范围或技能定位。已有散墨预算前缀也必须以这条付费轨迹为输入，避免通过无墨尾迹把伤害移到远处。

耗尽不立刻施法。正常松手或绘制时限到达时，统一结算一次；若超时先发生，继续等待原手指抬起。

## 5. 自然恢复与时间

恢复只在允许的活动状态运行：非有效绘制、非等待原手指抬起、非暂停／升级／后台／对局结束。有效绘制中停笔不动也不恢复。

建议用专门的“活动真实时间”推进资源与绘制截止时间，不能沿用受到慢动作影响的战斗步长。暂停和后台时间不能在返回时一次补算。

当前代码绘制慢动作是50%，不是任务书示例中的20%；本次不改慢动作比例。当前帧时间还有0.1秒截断，若直接累加该截断值，就不能严格保证真实3秒截止。实现时需处理这个正确性问题，但不扩大成性能重构任务。

建议正常松手、失败和超时均使用相同恢复延迟；超时后尚未抬指时禁止恢复，并在实际抬指后开始0.35秒延迟。系统回滚不是施法，应恢复到本笔之前的资源状态，不制造额外失败等待。以上延迟细节尚待确认。

### 首版回墨动画

- 真实资源在释放成功时立即增加。
- 墨条附近一次小型暖金回流与边缘亮光，局部完成，不跨整屏飞行。
- 墨条在0.25～0.4秒内显示增长；小字“回墨 +2.1”轻微上浮淡出。
- 低于1点的返还也能显示，不因取整成为“回墨 +0”。
- 自然恢复只增长填充，不一直播放粒子。
- 未成符没有回流，不弹刺眼“失败”；无墨余痕暗淡。
- 开始下一笔时，显示必须跟随最新资源值，不能被上一笔尚未结束的返还动画拉回旧值。

首版不显示“流畅”“完美”，也不做不同评级动画。以后做品质时再扩展，不预先制造评分感。

### 两个容易误改的地方

1. **已有quality会影响技能伤害。** 技能工厂使用`damage × (0.8 + 0.2 × quality)`。不能为了“普通成符10%返还”把所有识别结果的quality改成同一值；首版资源返还独立配置，原伤害计算保持原样。
2. **现有inkBudget不是剩余灵墨。** 它是散墨攻击路径的局部长度上限，默认1.5倍画幅。不能直接当成新资源余额，也不能未经讨论删除它、顺带扩大散墨伤害范围。新资源先负责付费轨迹，原有散墨范围约束继续保留并更名说明。

## 8. 状态与一次性结算

建议复用现有控制器，并让资源管理器明确区分：

`空闲 → 起笔待确认 → 有效绘制 → 结算 → 恢复延迟 → 恢复`

特殊分支：

- 有效绘制 → 耗尽余痕 → 松手／超时结算。
- 超时结算 → 等待原手指抬起 → 恢复延迟。
- 未提交绘制 → 系统取消 → 回滚。

每个gestureId基础费用只扣一次，路径只扣增量，结算、释放、返还都只能执行一次。绘制时余额已经反映消耗，所谓“待提交”只是允许撤销的交易记录，不能在提交时再扣一遍。

建议本笔记录：有效长度、已扣成本、付费轨迹末点、开始时间、交易状态、结束原因、是否耗尽、是否超时、实际返还。恢复计时与事务状态由同一资源逻辑管理，UI只读取和呈现。

## 9. 避免等待条：首轮数值怎样观察

以下只是在8点/秒、普通成符10%、0.35秒延迟下的计算，**不是游戏实测结果**。假设暂停绘制、站着恢复整笔净成本：

| 路径长度 | 净成本 | 恢复净成本所需时间（含延迟，不含绘制） |
|---|---:|---:|
| 0.2W | 8.1 | 约1.36秒 |
| 0.5W | 12.15 | 约1.87秒 |
| 1.0W | 18.9 | 约2.71秒 |
| 1.5W | 25.65 | 约3.56秒 |
| 2.0W | 32.4 | 约4.40秒 |

玩家不必每次回满才能行动，开局100也能支持连画。但资源见底后的连续节奏，仍可能让长笔明显吃亏。

仅恢复到8点需要约1.35秒；8点在没有恢复的本笔中，只支持约0.133W的路径（720宽下约96单位）。它是“能起笔”的门槛，不能保证画完圆或Z。UI不能把恢复到8点误导为“任何技能都够画”。

首轮同时观察：缺墨阻止起笔次数、缺墨后实际停手时长、平均每笔成本、正式成符比例、每分钟施法数，以及各符形是否明显被资源成本劝退。无需完整数据平台，开发日志和实战记录即可。

若频繁出现画不了、只能看怪靠近：先对比恢复8／12／16点每秒，必要时再降低基础6点或长度系数15。每次少量调整，记录结果；不要默认新增回墨技能、掉落物或额外冷却来补救。

最终“可接受等待多久”由实际体验讨论确定，当前不能宣称8点/秒已平衡。

## 10. 还需要讨论的规则

下表区分已经确认的选择与仍待讨论的建议；除标注“已确认”外，均未当作用户确认的实施规则。

| 待确认项 | 建议 | 原因／影响 |
|---|---|---|
| 绘制上限 | **已确认3秒** | 保持现有绘制窗口，不实施任务书的2秒 |
| 耗尽后付费轨迹恰好是一条线，允许一字斩吗？ | **已确认允许**；按整条付费轨迹识别，不提取局部线段 | 无墨余痕不参与识别；松手或3秒截止结算一次，不因耗尽立刻自动释放 |
| 失败后是否同样延迟0.35秒？ | 有成本的结算统一延迟 | 防止失败与成功恢复节奏不一致；原任务书只对正式施法写得最明确 |
| 超时未抬指，延迟从哪里算？ | 抬指后起算；等待抬指期间不恢复 | 最容易解释，也避免持续按住边回墨边重新起笔 |
| 耗尽后是否仍受绘制时限控制？ | 保持3秒上限，松手或超时先到先结算 | 避免无限停留在耗尽余痕状态，与“耗尽不立刻自动释放”兼容 |
| 有效起笔前静止按住，是否恢复／慢动作？ | 首版建议从按下暂缓恢复并保留现有慢动作；时间上限从按下算 | 避免免费按住长时间慢动作并恢复；误触不扣墨，但也不能无限拖长窗口。此处比任务书“没有有效绘制才恢复”更严格，需要确认 |
| 练习场用有限还是无限灵墨？ | **已确认默认无限＋有限灵墨测试开关** | 保留练习便利，又能验收真实消耗与耗尽；无限模式明确显示“无限”，不用旧3张符伪装 |
| 已收费但最终识别为过短无效，怎么结算？ | 达到有效起笔后按未成符保留成本，不回滚；兜底能否形成沿用现有条件 | 收费依据路径，成符还有几何尺寸条件；两种“短”不能混为一谈 |
| 玩家打开暂停等界面导致未提交回滚，是否允许？ | 首版按任务书回滚；不额外做反复暂停防刷机制 | 资源回滚与不施法对应，先保证正确；真正的系统取消与玩家主动取消策略后续可细化 |

### “耗尽后允许一字斩”具体是什么意思

例如起笔时只有8点墨。基础费用6点后，余下2点可支持约96逻辑单位的路径。

- 玩家先画一条横线，途中墨用完。截止用完时，**整条有墨支持的笔迹**是一条符合识别条件的直线。后续无墨移动只显示余痕。已确认松手或3秒到时，这条横线仍可释放一次一字斩，并按正式成符返还；耗尽时不会立即自动斩。
- 玩家想画Z，但画完第一横时就没墨。系统实际拿到的付费笔迹也是那条横线，它不知道玩家原本想继续画Z。因此同样可能识别为一字斩。
- 玩家画圆，画到半圆时没墨。有效笔迹是半圆，不能用回墨动画补足后半圆，也不能从弧线中抽一小段来凑直线；未匹配正式符则沿用散墨处理。

**此项已经确认：没墨的这笔仍能使用已经画出来的完整符。** 按照整条付费有效笔迹识别，满足正式符条件就正常释放与返还；未匹配正式符则按散墨处理。

正式返还只在结算成功后发生一次。不能在按着手指时因为回墨而重新延伸已经封存的付费轨迹。

### 接下来优先讨论的三个体验问题

1. **按下但还没真正画，是否停止恢复？** 建议允许进入绘制的有效战斗触摸从按下暂缓恢复，3秒从按下计时；无墨被拒绝的触摸和UI触摸不能停止恢复、不能重置延迟。短误触仍不收费。
2. **失败与超时后多久开始恢复？** 建议有成本的结算统一延迟0.35秒。超时仍按着时不恢复，抬指后再开始延迟；误触、无墨拒绝不重置延迟。系统取消仅回滚未提交费用，恢复沿用此前状态。
3. **恢复到8点是否代表“所有符都能画”？** 不代表，只够一条短路径。建议首版清楚展示剩余值与不足反馈，不新增第二个长短符门槛。实测如果复杂符经常画到一半断墨，优先调恢复或成本，不要求玩家背每个符的精确价格。

有限灵墨测试模式中的自动施放按钮，也需要一致规则。建议沿用已有生成完整手势的方式计算其路径成本；按钮不模拟长时间绘制，但不能免费获得回墨。若余额不足以覆盖完整生成路径，阻止本次自动施放且不扣费，避免“点击圆阵却截断成别的符”。这一项仅适用于练习辅助按钮，手绘仍采用实时消耗和耗尽截断规则，待实施前确认。

首版已明确**不做流畅／完美分级**，不需要再为品质阈值阻塞实施。

## 11. 后续实施顺序与验收

讨论确认后，在当前游戏内依次接入，不单独做Demo：

1. 资源配置与单笔交易；替换符纸检查与施法扣费。
2. 有效起笔、实时路径扣费、耗尽截断及取消回滚。
3. 普通成符返还、散墨失败、超时与等待抬指。
4. 自然恢复与活动真实时间；暂停／后台／结算覆盖。
5. HUD替换、小型回墨动画、无墨反馈及开发调试入口。
6. 网页与微信预览验收，实际玩连续战斗，再调整恢复和费用。

### 必须通过

- 新局100点；原固定次数与符纸充能不再限制正式战斗。
- 从100起画，在达到有效阈值及后续行笔时余额立即变化；停笔不扣，松手不重复扣。
- 相同路径在不同绘制速度、采样密度和手机尺寸下成本近似一致；测试需在双方均未超时条件下比较，不要求不同采样率完美重建未采到的弯曲。
- 误触0消耗；有效未成符0返还；整笔正式成符10%返还。
- 对返还上限7点、净成本最低6点和余额上限100进行边界检查。
- 耗尽在线段中间截断，暗淡余痕不改变识别与攻击；不会重复施法。
- 超时只提交一次，原手指未抬起不能开启下一笔；等待期间不恢复。
- 系统取消回滚未提交成本；已提交的超时笔不因后续取消获得退款。
- 暂停、升级、后台和结束不恢复；返回不补算隐藏时长。
- 成功释放即可回墨，无目标也有效；返还立即可用于下一笔，不等待动画。
- 回墨有金光、填充增长、“回墨 +N”，包括小数；连续施法时动画不显示错误余额。
- 一字斩、圆、箭头、Z及现有技能等级、范围和伤害保持原行为。
- 真机确认长屏安全区、生命与墨条可读性、暂停点击，以及连续绘制时是否频繁被迫等待。

开发调试复用现有入口，新增：余额／上限、当前状态、gestureId、有效长度、已扣成本、返还、剩余恢复延迟、结算原因、超时／耗尽标记；提供设为100／50／8／0、暂停恢复和开关回墨视觉。未确认正式成符时，“预计净成本”必须标注预测，不能提前假定会返还。
